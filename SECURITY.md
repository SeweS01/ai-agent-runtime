# Security policy

## Supported versions

Security fixes are applied to the current `main` branch. Tagged release support will
be documented when a stable release policy is introduced.

## Reporting a vulnerability

Do not open a public issue containing a vulnerability, credential, private path,
customer data, or exploit details. Use GitHub's **Security → Report a vulnerability**
flow when it is available. Otherwise contact the repository owner privately through
GitHub before sharing technical details.

Include the affected commit or release, impact, reproduction conditions, and a
minimal secret-free proof of concept. Never attach real tokens, provider profiles,
runtime databases, Telegram data, or production logs.
